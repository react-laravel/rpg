# Elemental skill effects

The ten current mage skills share the existing cast/travel/hit/tail clock, but now have distinct silhouettes: a tapered flame, faceted ice lance, branching lightning, falling rock, three curved arcane missiles, an ice field, a faceted shield, a three-element convergence, and a golden familiar-summoning seal. The summon resolves to the actual pet avatar when present, with a caster fallback. Impact signatures match those shapes rather than reusing the same orb/ring burst everywhere.

## Interaction and rendering guarantees

- Gameplay, server results, skill duration and authoritative hit times are unchanged. Damage releases at the hit; the canvas remains until its tail ends.
- Single-monster fallback respects `monsterHpBeforeRound`, just like the group display.
- Resource values and monster names are excluded from canvas drawing using measured, padded rectangles. Masks and actor anchors refresh on resize.
- One canvas, at most five targets and fourteen masks, DPR at most 2, and at most two million backing pixels. AOE particle detail decreases as target count increases. No persistent particle objects, new assets, or runtime dependencies.
- Reduced motion uses stationary elemental marks and a gentle fade; changing the preference during a cast settles it immediately. No whole-screen flash or camera shake.
- A new keyed round cancels the old clock. Timeline callbacks remain once-only under skipped frames, background-tab watchdog settlement, and synchronous callback re-entry.

## Verification

Run `npm test -- --maxWorkers=1`, `npm run type-check`, `npm run lint`, and `npm run build`.

Focused tests cover the timeline, React canvas lifecycle, all registered drawing profiles, anchor/mask geometry, and actual battle HP settlement/repeated rounds.

Offline Canvas evidence is generated by `output/skill-effects/render-offline.cjs` using the actual renderer and repository pixel assets. It requires Node, TypeScript and `@napi-rs/canvas`. The optional native Canvas tool is only used for local QA; it is not an application dependency. Rendered scenes approximate battle geometry and do not replace browser interaction checks.

The cloud browser's localhost restriction prevents end-to-end browser verification in this environment. No bypass, deployment, or production data changes are part of this work.
